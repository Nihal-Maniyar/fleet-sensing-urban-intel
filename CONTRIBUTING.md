# Contributing

Use a GitHub Issue to describe one small, testable unit of work. Include the owner/reviewer pair, relevant contract, acceptance criteria, and a demo or test expectation.

Create branches from `develop` using `feature/`, `fix/`, `docs/`, or `test/`. Open pull requests back to `develop`; only merge `develop` into `main` when the demo path is stable.

Before requesting review, check that the changed contract remains compatible, run relevant tests, and complete the pull-request checklist.

Suggested commits: `feat(edge): …`, `feat(api): …`, `fix(fusion): …`, `test(api): …`, `docs: …`, or `ci: …`.
